1.2.6. Экспертиза ИБ

Цель этапа: выявить риски проекта с точки зрения информационной и экономической безопасности и сформулировать требования ИБ к проекту, при необходимости дополнить скоуп проекта, архитектуру проекта требованиями ИБ, определить потребоность в ресурсе ИБ на проект.

Роли этапа: Бизнес-аналитик, Руководитель проекта, Руководитель портфеля проектов, Специалист ИБ

Условия на вход: 

  1. Техническое задание (бизнес-требования, раздел бизнес-анализ)
  2. Заполненный опросник "Требования ИБ к ИТ системам"

Шаги процесса:

Для проведения экспертизы необходимо оформить заявку в SimpleOne, в соответствии с инструкцией ниже.

  1. Определить размер ИБ-составляющей проекта
  2. Зайти на https://sd.lenta.com/
  3. Выбрать тип обращения "Провести экспертизу ИТ-проекта, системы или сервиса", приложить к заявке заполненный опросник "Требования ИБ к ИТ системам".
  4. Забронировать ресурс специалиста ИБ на проект. Для крупных проектов (от размера L и более обязательно закрепляется выделенный специалист от ИБ).
  5. Файл, полученный от ИБ по итогам решения заявки прикрепить в данном разделе пространства проекта.
  6. Если возникают вопросы по заключению ИБ можно назначить встречу для подробной консультации со специалистами ИБ. Лютинский Дмитрий 


Размер ИБ-составляющей проекта, определяется по критериям:

Размер проекта ИБПризнак, примерыКак работаем с проектом
Крупный

Новое мобильное приложение, новый сайт по работе с внешними контрагентами/клиентами, крупное облачное решение, есть конфиденциальные или персональные данные, новая система хранения данных.

Примеры крупных проектов: Лента-спутник, КЭДО, Замена hadoop, новая ITSM-система.

Маленький

Требования к информационной безопасности

Защита информации от несанкционированного доступа осуществляется средствами сетевой операционной системы, СУБД, и другими организационно-техническими мерами в соответствии с ЛНА ООО "Лента".

Требования к аудиту событий в информационной системе

Необходимо вести аудит событий входа/выхода пользователя в систему. Журнал аудита должен храниться не менее 3 месяцев. Для каждой записи базы данных необходимо предусмотреть хранение идентификатора учетной записи  пользователя  создавшего (изменившего) запись, а также дату этого создания (изменения). Для критичных данных необходимо хранить  историю этих изменений.

Требования к разграничению доступа к информации в системе

Для каждого пользователя должны быть заведены уникальные учетные записи за исключением особых случаев, связанных с выполнением функциональных обязанностей группой работников с одним приложением.

Список работников, использующих групповые учетные записи, должен быть строго определен. Групповые учетные записи могут быть созданы только для просмотра не конфиденциальной информации.

Доступ к критичной по параметрам целостности и конфиденциальности  информации, и ее модификация (редактирование, добавление и удаление) возможны строго по индивидуальным идентификаторам (использование групповых учетных записей в данном случае запрещено).

Для предупреждения искажения, утраты и утечки информации система должна предусматривать возможность разграничения прав доступа  к информации (чтение, редактирование, добавление и удаление) в соответствии с присвоенными ролями. Роли должны строго соответствовать функциональным обязанностям работника.

Требования при работе с конфиденциальной информацией

Для конфиденциальной информации необходимо в журнале аудита хранить дополнительно к  выше перечисленным требованиям и историю изменений данных.

При передаче конфиденциальной информации по каналам связи необходимо использовать средства криптозащиты, согласованные с УИБ ДОБ.

К конфиденциальной информации относятся персональные данные (ПДн) и информация, составляющая  коммерческую тайну ООО "Лента".

При обработке конфиденциальной информации необходимо в журнале аудита хранить:

  • идентификатор разработчика, который поместил данную информацию в Систему, а так же дату и время внесения этой информации; историю обращения пользователей к данной информации (идентификатор пользователя, дату и время обращения).
  • историю изменений данных.

К журналу аудита конфиденциальной информации должны иметь доступ только Ответственное лицо и сотрудники подразделения УИБ ДОБ с правами только на чтение данных.

Для выполнения требований по хранению истории изменений данных применяется резервное копирование и хранение резервных копий.

Организационные мероприятия. Учет и грифование документов с КТ

Для электронного учета документа, содержащего ИКТ, в ИС "____________" должна производиться его маркировка. Она осуществляется путем проставления  штампа (в правом верхнем углу титульного листа документа) с реквизитами, указанными в Процедуре П5-02 "Защита коммерческой тайны". Способ маркировки электронного носителя содержащего ИКТ выбирается согласно требований указанной Процедуры.

Требование к документации

Для ИСПДн необходимо оформить и соответствующим образом утвердить:

  1. Описание процессов обработки ПДн в ИСПДн.
  2. Технический паспорт на ИСПДн
  3. Акт классификации ИСПДн (утверждается Комиссией Ленты)
  4. Модель угроз безопасности персональным данным (формируется УИБ ДОБ, на основе вышеперечисленных документов).
