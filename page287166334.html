1.4. Preparing for start (Подготовка к старту проекта)

Цель этапа: Убедиться, что все необходимые артефакты этапов Open, Discovery, Approval investes, Prepearing for start в наличии (в соответствии с чек-листом), оценить доступность ресурсов для реализации проекта

Роли этапа: Руководитель проекта, Администратор домена, Администратор проекта, Руководитель портфеля проектов

Условия на вход: Сформирован Бизнес-кейс проекта, понятна потребность в ресурсах на проект

Шаги процесса:

  1. уведомить Руководителей доменов о необходимости включить потребность в ресурсный план на следующий квартал PI планирование - IT Strategy - Confluence (lenta.com)
  2. обсудить с Руководителем домена/направления о необходимости найма дополнительных сотрудников согласованных в рамках бюджета проекта
  3. сформировать роадмэп проекта в JIRA, включая WBS/Epic для бронирования ресурсов на проект
  4. Руководитель проекта инициирует первое собрание Управляющего комитета
  5. провести аудит в соответствии с чек-листом для этапов Open, Discovery, Approval investes, Prepearing for start

Результаты этапа:

  1. Оценена доступность ресурса, сформирована и согласована команда проекта 2.1.1 Команда проекта
  2. Оформлены заявки на найм
  3. Все документы проекта (по итогам этапа Discovery) в наличии в пространстве проекта confluence
  4. Протокол первого Управляющего комитета
  5. Все артефакты проекта этапов Open, Discovery, Approval investes, Prepearing for start в наличии, оформлены корректно, наполнены всей необходимой информацией о проекте.


Процедура запроса внешнего ресурса на проект:

  1. Определить Центр компетенций, который может выделить ресурс (сначала внутренний)
  2. В случае дефицита собственного ресурса - запросить в ЦК профиль необходимого ресурса для поиска (или создать его совместно)
  3. Найти активный тендер, в котором есть подобные специалисты (уточнить в ЦК, был ли проведен такой тендер, где указан список компаний, в которых можем запросить необходимый ресурс) - отсюда сформировать список контактов компаний
  4. На список компаний сделать рассылку с требованиями, предпочтительно указывать 100% нагрузку на некий период (чем неполную нагрузку) - в таком случае проще найти ресурс
  5. Далее провести интервью с кандидатами (совместно с ЦК), может быть выдано тестовое задание отобранным кандидатам
  6. Если нет тендера - то формируем ТЗ на тендер, далее в системе SRM НКЗ формируем заявку на тендер (В критичных случаях, если уже есть ресурс (которого нашли вне тендера сами) - в заявке на тендер можем написать обоснование выбора по уникальности)
  7. Ищем в рамках тендера компанию и специалиста (в рамках тендера можно просить присылать резюме) - выбор специалиста осуществляется совместно с ЦК
  8. После того, как определен ресурс - 
  9. Решить, какой это бюджет (как правило CAPEX, т.е. должен быть согласован PJF или согласовано выделение OPEX) и ИТ актив
  10. Создать заказ на этот ресурс (договорной документ в Wss - по шаблону договорного документа из тендера)
  11. ДО НАЧАЛА РАБОТЫ запросить и проверить доступы для сотрудника через IDM (предварительно он должен подписать соглашение о неразглашении) - обязательно в JIRA и Confluence
  12. Организовать онбординг нового сотрудника (желательно встречи с необходимыми ЦК), решить кто будет контролировать работу специалиста
  13. Ежемесячно сотрудник подписывает отчет, мы со своей стороны проверяем результаты работы, принимаем результат (артефакты должны быть переданы в ЦК, которые могут оценить его результат)
  14. В случае неисполнения сотрудником - делегировать вопрос в компанию от которой был выделен ресурс, попросить замену или мы меняем компанию.
