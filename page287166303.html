0.9.2. Аудит качества Управления проектом

Аудит качества управления проектом.

Аудит качества управления проектом - регулярное проведение аудита подходов к управлению проектом и соответствия существующей методологии проектного управления, принятой в ДИТ Лента. 

Аудит качества управления проектом подразумевает оценку наличия необходимых артефактов проекта в зависимости от жизненного цикла проекта.

Периодичность проведения:

Аудит качества управления проектом происходит на регулярной основе 1 раз в квартал в рамках аудита проектов портфеля.

Сроки: 

  1. Аудит проектов осуществляется с 1 по 15 число следующего месяца после отчетного квартала
  2. Результаты аудита по портфелям обсуждаются на ближайшей после 15-ого числа встречи РПП 

Критерии включения проекта в аудит проектов портфеля:

В аудит портфеля включаются все проекты и инициативы портфеля, за исключением инициатив в статусе Open.

Проекты, которые были включены в аудит портфеля, в течении года остаются в результатах аудита, за исключением переведенных в статус Отменен. 

Ответственность:

РПП отвечает за:

  • Организацию процесса аудита по портфелю 
  • Список проектов, которые входят в аудит
  • Корректность оценок аудита
  • План корректирующих действий по проектам, получившим в ходе аудита оценку ниже удовлетворительной
  • Проведение ревью корректировок
  • Общие рекомендации для РП портфеля по ведению артефактов проектов
  • Своевременное предоставление результатов аудита ЦК

РП отвечает за:

  • Проверку артефактов проекта перед аудитом (самопроверка)
  • Заполнение таблицы артефактов
  • Выполнение  плана корректирующих действий по проекту

ЦК PMO проводит выборочную или полную проверку результатов аудита проекта/портфеля не менее 2 раз в год.

Важность (вес) артефакта может быть изменен по решению ЦК PMO в момент старта годового цикла аудита.

Шкала оценки:

В процессе оценки артефактов проекта по каждому артефакту/документу формируется итоговая оценка по шкале от 1 до 5:

  • (пусто) - артефакт не актуален для проекта
  • 2 - артефакт актуален, но не заполнен
  • 3 - артефакт актуален, заполнен в должном виде, есть критичные замечания
  • 4 - артефакт актуален, заполнен в должном виде, есть некритичные замечания
  • 5 - артефакт актуален, заполнен в должном виде, нет замечаний

Важно! Если артефакт ведется не в стандартном для методологии формате, но содержит все требуемые методологией артефакты, оценка может быть максимальной. Если же не стандартная форма содержит лишь часть данных из стандартного формата, то оценка должна быть снижена.

Например, статус-отчет по проекту формируется не в формате Bi-weekly и содержит информацию по общему статусу по проекту в виде On-Page из презентаций Мастер-плана, при этом отсутствует информация по статусу КТ, план-графику, реестру рисков с указанием мероприятий с ответственными и сроками, перечню запланированных и выполненных задач отчетного периода, то оценка по артефакту Статус отчеты не может быть выше 4, поскольку On-Page содержит  информацию по статусу проекта, рискам, роадмапу, задачам отчетного периода, но верхнеуровневую, т.е. например, не позволяет понять каким образом осуществляется в проекте управление рисками.

Другой пример: статус-отчет по проекту формируется не в формате Bi-weekly и содержит только информацию о запланированных и выполненных задачах отчетного периода, при этом отсутствует информация о статусе проекта, рискам, роадмапу, КТ, то оценка по артефакту Статус отчеты не может быть выше 3, поскольку такой отчет не информативен и не дает понимания что с проектом. 

Итоговая оценка Качества управления проектом:

Итоговая оценка качества Управления проектом формируется как средневзвешенное значение оценок актуальных для проекта артефактов.

Допустимое (удовлетворительное) значение - 4,5 и выше.

Итоговая оценка по Руководителю проектов рассчитывается как среднее значение итоговых оценок всех проектов Руководителя проектов, вошедших в аудит.

Итоговая оценка по портфелю рассчитывается как среднее значение по итоговым оценкам всех проектов портфеля, вошедших в аудит. 

Итоговая оценка по портфелю рассчитывается по результатам каждого квартала с учетом ранее оцененных проектов, которые не вошли в аудит текущего квартала, но участвовали в аудите портфеля в текущем году. Например, проект был завершен 25.01.25 (переведен в статус Done) → проект включен в аудит 1 квартала, в последующих результатах аудита проект сохраняется и включен в итоговую оценку аудита.

Корректирующие действия:

В случае, если полученная оценка менее 4,5, то необходимы корректирующие действия для улучшения качества управления проектом, которые могут включать:

  • заполнение необходимых артефактов;
  • исправление ошибок;
  • улучшение полноты доступной информации по проекту;
  • улучшения в части регулярных действия по управлению проектом: протоколы, отчетность, контроль бюджета, контроль сроков и т.д.

Повторная оценка качества проекта:

После выявления отклонений в Управление проектом и проведения корректирующих мероприятий, улучшение итоговой оценки происходит в результатах следующего аудита, либо через повторное ревью, которое должно быть осуществлено до подачи итоговых результатов аудита по портфелю в текущем цикле аудита.

Рекомендации:

  1. Аудит проекта может осуществляться силами Администраторов проектов или Руководителями проектов, не являющимися АП и РП данного проекта  - перекрестный аудит. 
  2. Желательно регулярно менять аудитора проекта, в том числе из другого домена (т.е. каждый квартал новый аудитор). 
  3. Осуществлять сбор интересных практик по ведению артефактов/отличия между ведением одного и того же артефакта в проектах, обсуждать на встречах портфеля, информировать ЦК, как обмен практиками.
  4. Вести единую страницу в Confluence с результатами аудитов: общая оценка по портфелю, файл с результатами, перечень проектов, не вошедших в аудит, зафиксированные рекомендации/корректировки (общие/индивидуально по проектам)
  5. В файле с результатами аудита помечать те проекты, которые не были включены в текущий аудит (т.е. результат аудита по ним перенесен с предыдущего аудита)
  6. Если артефакт ведется не в стандартном для методологии формате, желательно добавить комментарий к ячейке c оценкой.
  7. Если артефакт неактуален для проекта, желательно добавить комментарий к соответствующей ячейке с пояснением неактуальности или в таблице артефактов в Confluence.
  8. В случае, если проект является продолжением другого проекта и наследует документацию другого проекта, то на уровне РПП желательно принять решение по ведению проектной документации проекта: объединение проектных пространств и соответственно артефактов, либо все же раздельное ведение 2-х проектных пространств. В случае разделения в артефактах могут быть ссылки на артефакты другого проекта, при этом оба проекта должны участвовать в аудите независимо. Если принято решение по объединению проектных пространств в одно, то в результатах аудита в столбцах проект и номер проекта указать оба проекта.
  9. В случае оценки ниже 5 причины снижения оценки указывать в примечании к соответствующей ячейке в файле аудита. Если замечаний много, то замечания можно оставить в виде комментариев к артефакту (на странице Confluence), а в примечании к ячейке указать см. в артефакте.
